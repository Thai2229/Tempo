Log in by the rhythm of your typing

Tempo learns how you type your password: how long you hold each key and how fast you move to the next. At login it checks that rhythm, as a second factor next to the password.

It is a soft signal, not a lock. The numbers below say how soft.

Try it

Your keys never leave the browser. Only anonymized timings are sent: how long each key was held and the gaps between keys, with every key name replaced by a placeholder.

How it works

  1. Capture. The browser records when each key goes down and up, in milliseconds.
  2. Anonymize. Before sending, every key becomes a placeholder (x, k0, k1, ...). The server never learns what was typed.
  3. Embed. Each keystroke becomes three timings. A small PyTorch encoder turns the attempt into a point on a sphere. Typing it 10 times gives your template, the mean point.
  4. Compare. At login, accept if the new attempt is close enough to the template. Replays are rejected, repeated failures lock the account, and the template adapts slowly as your rhythm drifts.

Honest numbers

Measured on the CMU Keystroke Dynamics Benchmark: 51 typists, one password, 10 enrollment attempts, test users never seen in training, threshold chosen on validation users only. Equal error rate (EER, lower is better), mean ± std over 5 user splits.

  • It is a tie, not a win. Tempo matches classic detectors from 2009. With 8 test users per split, any single number is about ± 5 points.
  • 10 enrollment attempts is few. The classic study used 200.
  • A soft signal, not a lock. At roughly 1 error in 5, it cannot authenticate anyone on its own. Use it next to a password, to add friction for an attacker or to raise a flag.

Per-seed tables and failure cases: docs/RESULTS.md in the repository.

Use it on your site

Add the script and attach it to your password field. The browser gets back only a signed, single-use token valid for 60 seconds. Your server then asks Tempo whether the rhythm matched.

<script src="https://YOUR-TEMPO-HOST/v1/tempo.js" defer></script>
tempo.attach(document.getElementById("pw"), {sitekey: "pk...", userIdField: "#username"});
POST /v1/siteverify {secret, token}  ->  {success, user_id, rhythm_match, risk}

Always call siteverify from your server and compare the returned user_id with the account that logged in. Setup, enrollment tickets and the threat model are in docs/SERVICE.md.

Privacy

Keystroke timings are biometric data. The page sends anonymized events only: no key names and no password, just times and placeholders. Logs carry a hash of the user id and the outcome, never timings or scores. The repository contains no user templates, databases or model files.
